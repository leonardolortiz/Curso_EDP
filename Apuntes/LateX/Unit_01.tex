	\begin{frame}{Lineamientos de Diseño RTL}
	\begin{itemize}
		\item La partición de un diseño digital en una serie de módulos es importante.
		\item Un módulo no debe ser demasiado pequeño ni demasiado grande.
		\item Siempre que sea posible, el diseño debe dividirse de manera que los límites del módulo terminen en salidas de registros. Esto hará que sea más fácil sintetizar el módulo de nivel superior o síntesis jerárquica en cualquier nivel con limitaciones de tiempo.
		\item El diseñador también debe asegurarse de que ninguna combinación de nubes cruce los límites del módulo. Esto da a la herramienta de síntesis más facilidades para generar lógica optimizada.
	\end{itemize}
	\end{frame}

	\section{Lenguajes de Descripción de Hardware - HDL}
	
	\begin{frame}{Lenguajes de Descripción de Hardware - HDL}
		En la actualidad se vuelve indispensable diseñar, modelar y simular el funcionamiento del hardware, principalmente en la industria ya que de este modo se evitan grandes pérdidas por errores de diseño. Para poder lograr esto existen los "Lenguajes de Descripción de Hardware".\newline
		
		Los Lenguajes de Descripción de Hardware (HDL) son una metodología de diseño digital de hardware a través de software.
		
		\note{
			HDL incluye explícitamente la noción de tiempo.
		}
	\end{frame}
	
	\begin{frame}{Lenguajes de Descripción de Hardware - HDL}
		\textbf{Ventajas} \newline
		
		\begin{itemize}
			\item INDEPENDIENTE DE LA TECNOLOGÍA\newline
			\item SOPORTA VARIOS ESTILOS DE DESCRIPCIÓN (Behavioral, Dataflow, Structured, Switch)\newline
			\item AHORRO DE TIEMPO Y COSTOS\newline
		\end{itemize}
		
		
		\note{
			INDEPENDIENTE DE LA TECNOLOGÍA: el mismo modelo puede ser sintetizado en librerías de distintos fabricantes.
			SOPORTA 3 ESTILOS DE DESCRIPCIÓN: (Behavioral, Dataflow, Structured)
			AHORRO DE TIEMPO Y COSTOS: facilita las correccionesen el diseño debidas a fallos de diseño o cambios en las especificaciones.
			
		}
	\end{frame}
	
	
	\begin{frame}{Lenguajes de Descripción de Hardware - HDL}
		\textbf{Módulos} 
		
		El módulo es la unidad básica de diseño, en la que se describe el funcionamiento de alguna unidad lógica. Puede existir un sólo módulo o un conjunto de módulos que se instancian con un módulo estructural.\newline
		
		
		\textbf{Entradas y Salidas} 
		
		Un módulo define la información que describe la relación entre las entradas y salidas de un circuito lógico. Las entradas y salidas están definidas por las palabras reservadas según sea el caso del lenguaje utilizado.\newline
		
		\textbf{Primitivas} 
		
		Elementos lógicos predefinidos, que son elementos estructurales que se pueden instanciar en un diseño más grande para formar una estructura más compleja.(Ej. en Verilog: and, or, xor, not)
		
		
		\note{
			Un mpodulo Verilog es una representación de software de la estructura y comportamiento del hardware físico.	
		}
		
	\end{frame}

		use IEEE.STD_LOGIC_1164.ALL;
		
		entity seq_detector is
		port (
		clk          : in  STD_LOGIC;
		rst          : in  STD_LOGIC;
		bit_in       : in  STD_LOGIC;
		seq_detected : out STD_LOGIC
		);
		end seq_detector;
		
		architecture Behavioral of seq_detector is
			type state_type is (S0, S1, S2);
			signal state, next_state : state_type;
		begin
			process(clk, rst)
			begin
				if rst = '1' then
					state <= S0;
				elsif rising_edge(clk) then
					state <= next_state;
				end if;
			end process;
		\end{lstlisting}

	void clock_tick(bool bit_in) {
		seq_detected = false;
		switch (state) {
			case S0:
			state = (bit_in) ? S1 : S0;
			break;
			case S1:
			state = (!bit_in) ? S2 : S1;
			break;
			case S2:
			if (bit_in) {
				state = S1;
				seq_detected = true;
			} else {
				state = S0;
			}
			break;
		}
	}

\begin{frame}{Lenguajes de Descripción de Hardware - Resumen}
	
	 \textbf{VHDL}:
	 \begin{itemize}
	 	\item Fuertemente tipeado (ADA-like verbose syntax)
	 	\item Muy estricto en tipos
	 	\item Considerado más robusto por algunos ingenieros
	 \end{itemize}
	
	\textbf{Verilog}:
	 \begin{itemize}
		\item Lenguage clásico HDL
		\item Sintaxis similar a C
		\item No tiene muchas características modernas como typedef, class o interface
	\end{itemize}

	\textbf{SystemVerilog}:
	 \begin{itemize}
		\item Extiende Verilog con mejoras como logic, enum, typedef, interface, class, randomization, etc.
		\item Sintaxis compatible con Verilog, pero más poderoso para testbenches y sistemas complejos
		\item Permite diseño orientado a objetos (especialmente en verificación)
	\end{itemize}
\end{frame}

\begin{frame}{Lenguajes de Descripción de Hardware - Resumen}
	
	\textbf{SystemC}:
	\begin{itemize}
		\item Mayor Abstracción
		\item Diseño de Hardware y Software Conjunto
		\item Exploración de Arquitecturas
		\item Productividad
		\item Simulación Rápida
		\item Flexibilidad
	\end{itemize}
	
		\note{
			\begin{itemize}
			\item Mayor Abstracción:
			SystemC opera a un nivel más alto de abstracción que VHDL y Verilog, lo que permite a los diseñadores centrarse en la funcionalidad del sistema en lugar de los detalles de implementación.
			\item Diseño de Hardware y Software Conjunto:
			SystemC facilita el modelado y la verificación conjunta de hardware y software, lo que puede llevar a un mejor diseño del sistema y a la identificación temprana de problemas.
			\item Exploración de Arquitecturas:
			La alta abstracción y la capacidad de modelado flexible de SystemC permiten una exploración más eficiente de diferentes arquitecturas y la distribución de funcionalidades entre hardware y software.
			\item Productividad:
			La capacidad de modelar a un nivel más alto de abstracción puede aumentar la productividad del diseño y reducir el tiempo de desarrollo.
			\item Simulación Rápida:
			SystemC ofrece simulaciones más rápidas que VHDL y Verilog debido a su mayor nivel de abstracción.
			\item Flexibilidad:
			SystemC es un lenguaje versátil que puede utilizarse para modelar tanto a nivel de sistema como a nivel de transferencia de registros (RTL). 
		\end{itemize}
			
			Desventajas:
		\begin{itemize}
			\item Curva de Aprendizaje:
			Aunque SystemC puede ser más fácil de aprender para aquellos con experiencia en programación en C++, puede tener una curva de aprendizaje más pronunciada para aquellos que están familiarizados con VHDL o Verilog, especialmente en lo que respecta a la programación orientada a objetos.
			\item Herramientas de Síntesis:
			Aunque las herramientas de síntesis basadas en SystemC están mejorando, pueden ser menos maduras y sofisticadas que las disponibles para VHDL y Verilog.
			\item Popularidad:
			Aunque SystemC está ganando popularidad, especialmente en Asia y Europa, su adopción no es tan generalizada como la de VHDL y Verilog en la industria. 
		\end{itemize}
			}
\end{frame}

\begin{frame}{Lenguajes de Descripción de Hardware - Resumen}
	Ventajas de los Lenguajes de Descripción de Hardware (HDL)\newline
	\begin{itemize}
		\item \textbf{Design Verification}: permiten la verificación funcional temprana de los diseños. Los diseñadores trabajan a nivel de transferencia de registros (RTL), optimizando y modificando la descripción RTL hasta que cumpla con la funcionalidad deseada, lo que ayuda a eliminar la mayoría de los errores de diseño
		\item \textbf{Simulation}: permiten simular diseños, lo que posibilita realizar pruebas exhaustivas antes de su implementación en hardware
		\item \textbf{Parallel Programming}: VHDL (Very High-Speed Integrated Circuit Hardware Description Language, lenguaje de descripción de hardware para circuitos integrados de muy alta velocidad) también puede servir como lenguaje de programación paralelo de uso general
	\end{itemize}
\end{frame}


\begin{frame}{Lenguajes de Descripción de Hardware - Resumen}	
	Desventajas de los Lenguajes de Descripción de Hardware (HDL) \newline
	\begin{itemize}
		\item \textbf{Learning Curve}: tienen una curva de aprendizaje pronunciada para los principiantes debido a su sintaxis y conceptos específicos.
		\item \textbf{Debugging Challenges}: La depuración de diseños basados en HDL puede resultar compleja, especialmente cuando se trata de circuitos de gran tamaño.
		\item \textbf{Limited Visualization}: A diferencia de los diseños basados en esquemas, los HDL carecen de representaciones visuales, lo que dificulta la visualización del circuito.
		\item \textbf{Hardware Constraints}: Los HDL no siempre convierten perfectamente hardware real, y ciertas construcciones pueden no ser sintetizables.
	\end{itemize}
\end{frame}


\begin{frame}{Lenguajes de Software - Resumen}
	Ventajas de los Lenguajes de Software\newline
	\begin{itemize}
		\item \textbf{Versatility}: Los lenguajes de programación pueden utilizarse para una amplia gama de aplicaciones más allá del diseño de hardware.
		\item \textbf{Abstraction}: Los lenguajes de programación de alto nivel proporcionan abstracción, lo que facilita la expresión de algoritmos y lógica complejos.
		\item \textbf{Rich Libraries}: Los lenguajes de programación ofrecen amplias bibliotecas y marcos de trabajo para diversas tareas.
	\end{itemize}
\end{frame}

\begin{frame}{Lenguajes de Software - Resumen}
	Desventajas de los Lenguajes de Software\newline
	\begin{itemize}
		\item \textbf{Performance Overhead}: Los lenguajes interpretados pueden tener una sobrecarga de rendimiento en comparación con los lenguajes de bajo nivel como C o lenguaje ensamblador.
		\item \textbf{Resource Consumption}: Las aplicaciones de software consumen recursos del sistema (CPU, memoria), lo que afecta al rendimiento general del sistema.
		\item \textbf{Security Risks}: Los lenguajes de programación pueden introducir vulnerabilidades de seguridad si no se manejan con cuidado.
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Concurrency}
	La concurrencia, en el contexto de la programación, se refiere a la capacidad de un programa para descomponerse en partes que pueden ejecutarse de forma independiente entre sí.
\end{frame}

\begin{frame}{Puntos claves: Concurrency}

	\textbf{HDLs}:
	\begin{itemize}
		\item La concurrencia en la descripción del hardware se refiere a la ejecución simultánea de múltiples operaciones dentro de un circuito digital.
		\item Modelan la naturaleza paralela de las operaciones del hardware, donde las señales se propagan a través de diferentes caminos simultáneamente y los componentes interactúan entre sí en paralelo.
		\item VHDL y Verilog admiten de forma inherente la ejecución concurrente, lo cual es crucial para simular cómo funcionan simultáneamente las diferentes partes de un circuito.
		\item Los HDL incluyen construcciones (procesos en VHDL, bloques always en Verilog) para modelar el comportamiento concurrente.
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Concurrency}
	\textbf{GPLs}:
	\begin{itemize}
		\item Suelen ejecutar instrucciones de forma secuencial, aunque el paralelismo y la concurrencia pueden lograrse explícitamente mediante hilos (threads), procesos o técnicas de programación asíncrona.
		\item Sin embargo, operan a un nivel más alto de abstracción y son gestionadas por el programador.
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Timing}
	
	\textbf{HDLs}:
	\begin{itemize}
		\item El estado de tiempos en la descripción del hardware se refiere a los retrasos de propagación y las restricciones de sincronización asociados con las transiciones de señales y las interacciones de los componentes dentro de un circuito digital.
		\item Proporcionan construcciones de tiempo para especificar restricciones de sincronización y retrasos, reflejando el comportamiento en tiempo real de los circuitos digitales.
		\item La información de sincronización es fundamental para la simulación y síntesis precisas de los diseños de hardware. 
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Timing}
	\textbf{GPLs}:
	\begin{itemize}
		\item Las consideraciones de temporización en los GPL suelen gestionarse en un nivel de abstracción superior, por ejemplo, mediante funciones de suspensión o retardo, o se abstraen por completo en las aplicaciones de software.
		\item No disponen de construcciones integradas para especificar restricciones de temporización al nivel de los HDL.
		\item La información de temporización en los GPL es gestionada por el sistema operativo y no refleja directamente el comportamiento de temporización de los circuitos digitales.
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Applications}
	
	\textbf{HDLs}:
	\begin{itemize}
		\item Incluyen amplias funciones para la simulación y la verificación. Los ingenieros crean testbenches y herramientas de simulación para validar el comportamiento de los diseños de hardware en diferentes escenarios.
		\item Las herramientas de síntesis convierten las descripciones HDL en implementaciones a nivel de compuertas, que luego se utilizan para fabricar el hardware real.
	\end{itemize}
\end{frame}

\begin{frame}{Puntos claves: Applications}
	\textbf{GPLs}:
	\begin{itemize}
		\item Se centran en la corrección, la eficiencia y la funcionalidad de los algoritmos. Los desarrolladores utilizan herramientas de depuración, frameworks de pruebas y herramientas de análisis de código para garantizar la calidad del software.
	\end{itemize}
\end{frame}

\begin{frame}{Programación controlada por eventos}
	\textbf{Event queue}
	
	\begin{figure}[htb]
		\centering
		\includegraphics[width=0.9\textwidth]{images/Event_queue}
	\end{figure}

	
	\note{
	En algunos casos, el dispacher y sus controladores (handlers) podrían no ser capaces de gestionar los eventos tan rápido como llegan. En tales casos, la solución consiste en almacenar en un búfer el flujo de entrada de eventos mediante la introducción de una cola (queue) de eventos en dicho flujo, entre el generador de eventos y el dispacher. Los eventos se añaden al final de la cola tan rápido como llegan, y el dispacher los retira del principio tan rápido como le es posible.\newline
	Las aplicaciones GUI suelen incluir una cola de eventos. Eventos importantes, como los clics del ratón, pueden requerir cierto tiempo para su gestión. Mientras tanto, otros eventos, como los de movimiento del ratón, pueden acumularse en el búfer. Cuando el dispacher vuelve a estar libre, puede descartar rápidamente los eventos de movimiento del ratón que se pueden ignorar y vaciar la cola de eventos rápidamente.
	}
	
\end{frame}

\begin{frame}{Arquitecturas controladas por eventos - Frameworks}
	 Un framework es:
	\begin{itemize}
		\item una estructura básica que soporta o engloba algo más.
		\item una visión general, esquema o esqueleto, dentro del cual se pueden añadir detalles.
		\item un entorno de software extensible que se puede adaptar a las necesidades de un dominio específico.
		\item un conjunto de clases que proporciona una solución general a un problema de aplicación. Un framework suele perfeccionarse para abordar el problema específico mediante la especialización o mediante tipos o clases adicionales.
		\item Un componente que permite extender su funcionalidad mediante la escritura de módulos complememtarios (``extensiones del framework''). El desarrollador de extensiones escribe clases derivadas de las interfaces definidas por el framework.
	\end{itemize}
\end{frame}

\begin{frame}{Arquitecturas controladas por eventos - Frameworks}
	Un framework es: (continuación) \newline
	
	\begin{itemize}
		\item Un conjunto de software diseñado para una alta reutilización, con plug-points específicos para la funcionalidad requerida por un sistema en particular. Una vez proporcionados los plug-points, el sistema mostrará un comportamiento centrado en ellos.
	\end{itemize}
	\vspace{0.7cm}
	El patrón que subyace al concepto de un framework es el patrón Handlers. Las extensiones del framework o complementos son controladores de eventos.
	
\end{frame}
